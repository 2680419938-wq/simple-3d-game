DragonMan 动作导入器（外部动作库 → 本角色）
================================================

一、最快的用法
1. 把 Mixamo 下载的 FBX（或任意标准命名的人形 FBX / BVH）丢进  AnimLib\in\
2. 双击  导入动作.cmd     ← 会处理 in\ 里所有 .fbx/.bvh
   （也可以把单个 FBX 直接拖到 导入动作.cmd 上）
3. 产物：
   - AnimLib\out\DragonMan_Std_<clip>.glb   含 Idle/Run/Walk + 你的新动作
   - AnimLib\out\report_<clip>.json          映射表、逐帧最低点、膝角、髋起伏
   - 同时复制一份到 dragon-man-final\ 和 web-preview\public\
   - 命令行会打印预览地址：http://127.0.0.1:5199/?glb=/DragonMan_Std_<clip>.glb
     （先双击 启动预览.cmd 起服务）

二、它做了什么
- 按骨名把源骨架映射到我们 70 根骨（自动去 mixamorig 前缀、大小写/下划线/点号归一，
  并对 pelvis→Hips、LeftLowerLeg→LeftLeg 这类常见别名做了同义词表）
- 逐帧取源骨的世界旋转增量，套到我们骨骼上（骨长/朝向/roll 差异全部自动抵消：
  实测每骨世界旋转误差 0.000°）
- 髋部位移按"腿长比"缩放（我们 0.4548 m / 源腿长），避免大步幅把人拽飞
- 膝盖超过上限自动钳制（默认 90°，二分求解）
- 地面修正：逐帧算蒙皮最低顶点，"只抬不压"（默认），所以跑步的腾空帧会保留
- 尾巴 12 根骨源里没有 → 程序化摆动（默认 ±5°/节，相位递增）
- 导出参数与既有交付件完全一致（JPEG 90、70 骨、4 材质、只导 3 个网格）

三、可调参数（在 .cmd 里或直接调脚本时加）
  --knee 90            膝屈曲上限（度）
  --ground-push 1      强制每帧踩地（默认 0 = 只抬不压，保留腾空）
  --stride-scale auto  水平位移缩放；auto = 腿长比，也可以给死数字
  --tail-sway 0        关掉尾巴摆动
  --base <blend>       以哪套骨架为底（默认 v3 的 Run 版，含 Idle/Run/Walk）

四、验证工具
  blender -b --python AnimLib\verify_retarget.py -- <源FBX> <产物.blend> <clip> <输出json>
  报告每根骨的最大/平均世界旋转误差——这是我们和源动作"是否等价"的硬指标。

五、已知限制（都是实测过的）
- 这是"分件拼装 + 短腿 Q 版"角色：腿长只有 0.4548 m（身高 2.010 m）。人类/写实动作
  套进来会出现深蹲、步幅被压缩，属于几何必然；需要"看起来像跑"的动作时，优先选
  步幅小、频率快的 clip。
- Mixamo 下载时务必勾 "In Place"（不带根位移），否则位移会被当作角色位移叠加。
- 源里没有的骨（小指、眼、下巴、我们多出的 12 根尾巴骨）不会被驱动：尾巴由程序摆动
  接管，手是 4 指（拇指/食指/中指/无名指），小指通道忽略。
- 手指/脚趾小岛是刚性绑定的，弯指节不会有皮肤褶皱（这是资产本身的结构，不是导入器的问题）。

六、本次自测（合成 Mixamo 规范人形，22 骨、厘米单位、A-Pose 40°、腿长 0.86 m、19 帧跑）
- 映射 17/17 根骨，每骨世界旋转误差 0.000°（19 帧全帧）
- 地面：修正前最低 -0.1618 m → 修正后 -0.000 / 最高 +0.0639 m（6 帧腾空）
- 膝屈曲 0–63°，髋高 0.6099–0.7717 m，导出 10,570,896 B / 70 关节 / 4 材质 / 12 张 JPEG
- 产物在 AnimLib\test\（源）与 AnimLib\out\（结果）
